# Повторный аудит Askane 0.10.2-fix

## Область проверки

Локальный исходный код lexer/parser/compiler/bytecode/VM/value, стандартные модули,
Win32 FFI, CLI, зависимости и текстовый поиск возможных секретов. Внешних Rust
зависимостей нет. Проверка не является доказательством отсутствия уязвимостей.
Git CLI недоступен в PATH, поэтому история коммитов и ранее удалённые секреты
не проверялись. Поиск в текущих rs/toml/md/ask/lock не обнаружил явных ключей или
паролей; это эвристика, не полноценный secret scanner.

## Исправления

1. **Высокий: импорт без расширения.** `.ask` добавлялся после проверки пути.
   Теперь расширение добавляется до canonicalize и проверки границ.
2. **Высокий: раскрытие данных через сеть/аргументы.** В sandbox блокируются HTTP,
   sys.args, sys.exit и mem. Окружение уже блокировалось. `mem` требует одновременно
   trusted VM и переменную opt-in; удалён обход защиты через cfg(test).
3. **Высокий: переполнение нативного стека.** Добавлены проверки унарной рекурсии,
   присваиваний, else-if и длинных цепочек AST; ограничена глубина импортов.
4. **Высокий: внедрение HTTP заголовков.** Проверяется строковый Content-Type,
   имена dictionary headers допускают только HTTP token characters.
5. **Средний: сетевые утечки/зависание.** Отключены redirect и автоматическая
   аутентификация Windows; добавлены таймауты, пределы запросов, проверки URL.
   Ошибка запроса больше не содержит полный URL с потенциальными токенами.
6. **Средний: исчерпание ресурсов.** Бюджет VM, bounded file reads, регулярные
   файлы, глубина форматирования/JSON, размер JSON-вывода между узлами.
7. **Средний: обрезание bytecode индексов.** Переполнение таблиц констант,
   upvalue lists и locals ведёт к ошибке компиляции; литералы коллекций ограничены.
8. **Средний: несовместимый JSON.** Запрещены ведущие нули, пустые дроби/экспоненты,
   non-finite числа и неэкранированные управляющие символы.
9. **Средний: Win32 gfx.** Уточнён layout MSG (lPrivate), снят RefCell borrow перед
   DestroyWindow, чтобы синхронный callback не вызвал panic через FFI. Числовые
   аргументы ограничены для предотвращения overflow и чрезмерно длинных линий.
10. **Средний: Windows пути.** Отклоняются device names, ADS и неоднозначные
    завершающие точки/пробелы. Добавлены ignore-правила распространённых secret files.

## Остаточные ограничения

- canonicalize + open — TOCTOU: другой процесс может заменить путь между операциями.
  Hard links позволяют обращаться к содержимому того же файла под другим именем.
  Файловая политика не является полноценной ОС-песочницей.
- Разрешены чтение/запись всех файлов внутри корня: не помещать рядом со скриптом
  личные данные. Сеть в trusted mode может обращаться к локальным/частным адресам.
- Нет общего учёта heap. Циклические Rc-графы не освобождаются; повторные конкатенации,
  крупные коллекции и глубокие значения могут исчерпать память или стек при Drop.
  Бюджет инструкций не ограничивает стоимость одной native-функции и весь wall time.
- Некоторые unchecked stack accesses VM полагаются на корректность компилятора;
  verifier bytecode и масштабный subprocess fuzzing ещё нужны.
- JSON с одиночными surrogate всё ещё заменяется U+FFFD; duplicate keys принимаются.
- GUI запускает дочерний процесс, но его остановка и доставка сообщений требуют
  ручного Windows-тестирования; отказоустойчивый Job Object и полное закрытие pipe
  остаются задачами следующего этапа.
- HTTP ошибки чтения/статуса ещё могут давать частичный ответ; таймауты — на операции,
  не общий deadline. Полноценная поддержка IPv6 URL пока отсутствует.
- mem trusted mode по-прежнему использует числовые handles и умеет запись памяти.
- GUI lifecycle проверен по коду; интерактивные окна и живые HTTPS-серверы не запускались.
- Публикуемый бинарник может содержать build paths/debug metadata. Для релизов нужны
  отдельная сборочная среда, remap-path-prefix, проверка артефактов и подпись.

## Регрессии

Добавлены проверки рекурсивного синтаксиса/AST-цепочек, восстановления VM с захваченными
locals после ошибки, instruction budget, блокировки private API, строгого JSON,
глубины сериализации, Windows special paths, HTTP injection и запрета сети.
Результаты запуска проверок приведены в итоговом сообщении аудита.
