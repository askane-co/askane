# Повторный аудит Askane 0.10.2-fix

## Область проверки

Локальный исходный код lexer/parser/compiler/bytecode/VM/value, стандартные модули,
Win32 FFI, CLI, зависимости и текстовый поиск возможных секретов. Внешних Rust
зависимостей нет. Проверка не является доказательством отсутствия уязвимостей.
Git CLI недоступен в PATH, поэтому история коммитов и ранее удалённые секреты
не проверялись. Поиск в текущих rs/toml/md/ask/lock не обнаружил явных ключей или
паролей; это эвристика, не полноценный secret scanner.

## Исправления

1. **Высокий: импорт без расширения.** `.ask` добавлялся после проверки пути.
   Теперь расширение добавляется до canonicalize и проверки границ.
2. **Высокий: раскрытие данных через сеть/аргументы.** В sandbox блокируются HTTP,
   sys.args, sys.exit и mem. Окружение уже блокировалось. `mem` требует одновременно
   trusted VM и переменную opt-in; удалён обход защиты через cfg(test).
3. **Высокий: переполнение нативного стека.** Добавлены проверки унарной рекурсии,
   присваиваний, else-if и длинных цепочек AST; ограничена глубина импортов.
4. **Высокий: внедрение HTTP заголовков.** Проверяется строковый Content-Type,
   имена dictionary headers допускают только HTTP token characters.
5. **Средний: сетевые утечки/зависание.** Отключены redirect и автоматическая
   аутентификация Windows; добавлены таймауты, пределы запросов, проверки URL.
   Ошибка запроса больше не содержит полный URL с потенциальными токенами.
6. **Средний: исчерпание ресурсов.** Бюджет VM, bounded file reads, регулярные
   файлы, глубина форматирования/JSON, размер JSON-вывода между узлами.
7. **Средний: обрезание bytecode индексов.** Переполнение таблиц констант,
   upvalue lists и locals ведёт к ошибке компиляции; литералы коллекций ограничены.
8. **Средний: несовместимый JSON.** Запрещены ведущие нули, пустые дроби/экспоненты,
   non-finite числа и неэкранированные управляющие символы.
9. **Средний: Win32 gfx.** Уточнён layout MSG (lPrivate), снят RefCell borrow перед
   DestroyWindow, чтобы синхронный callback не вызвал panic через FFI. Числовые
   аргументы ограничены для предотвращения overflow и чрезмерно длинных линий.
10. **Средний: Windows пути.** Отклоняются device names, ADS и неоднозначные
    завершающие точки/пробелы. Добавлены ignore-правила распространённых secret files.

## Остаточные ограничения

- canonicalize + open — TOCTOU: другой процесс может заменить путь между операциями.
  Hard links позволяют обращаться к содержимому того же файла под другим именем.
  Файловая политика не является полноценной ОС-песочницей.
- Разрешены чтение/запись всех файлов внутри корня: не помещать рядом со скриптом
  личные данные. Сеть в trusted mode может обращаться к локальным/частным адресам.
- Нет общего учёта heap. Циклические Rc-графы не освобождаются; повторные конкатенации,
  крупные коллекции и глубокие значения могут исчерпать память или стек при Drop.
  Бюджет инструкций не ограничивает стоимость одной native-функции и весь wall time.
- Некоторые unchecked stack accesses VM полагаются на корректность компилятора;
  verifier bytecode и масштабный subprocess fuzzing ещё нужны.
- JSON с одиночными surrogate всё ещё заменяется U+FFFD; duplicate keys принимаются.
- GUI запускает дочерний процесс, но его остановка и доставка сообщений требуют
  ручного Windows-тестирования; отказоустойчивый Job Object и полное закрытие pipe
  остаются задачами следующего этапа.
- HTTP ошибки чтения/статуса ещё могут давать частичный ответ; таймауты — на операции,
  не общий deadline. Полноценная поддержка IPv6 URL пока отсутствует.
- mem trusted mode по-прежнему использует числовые handles и умеет запись памяти.
- GUI lifecycle проверен по коду; интерактивные окна и живые HTTPS-серверы не запускались.
- Публикуемый бинарник может содержать build paths/debug metadata. Для релизов нужны
  отдельная сборочная среда, remap-path-prefix, проверка артефактов и подпись.

## Регрессии

Добавлены проверки рекурсивного синтаксиса/AST-цепочек, восстановления VM с захваченными
locals после ошибки, instruction budget, блокировки private API, строгого JSON,
глубины сериализации, Windows special paths, HTTP injection и запрета сети.
Результаты запуска проверок приведены в итоговом сообщении аудита.

## Изменения и аудит 0.11.0 – 0.13.0

1. **Гранулярные права (0.11.0, 0.13.0):** добавлены раздельные флаги `--allow-net[=hosts]`,
   `--allow-read[=dirs]`, `--allow-write[=dirs]`, `--allow-env[=vars]`, `--allow-args`,
   `--allow-clipboard`, `--max-steps=N` и `--timeout=MS`. Импорты наследуют права VM.
2. **Обработка ошибок (0.11.0):** добавлен `try / catch / throw` с раскруткой стека и
   закрытием upvalues; превышение лимита инструкций песочницы не перехватывается.
3. **Укрепление GUI и clipboard (0.12.0, 0.13.0):**
   - временные файлы GUI создаются атомарно с уникальным именем (`create_new`) и удаляются;
   - аргументы Windows квотируются, флаги GUI проходят строгий allowlist;
   - дочерний процесс GUI привязывается к Windows Job Object (fail-closed при ошибке);
   - в `clipboard` добавлена проверка `GlobalSize` и лимит 8 MiB на чтение и запись.
4. **VM, verifier и секреты (0.13.0):**
   - добавлен предзапусковый `verify_proto` (проверка границ констант, локальных слотов,
     upvalues, jump-адресов и замыканий);
   - добавлен wall-clock deadline (30 секунд по умолчанию в песочнице);
   - в `log` добавлено маскирование секретов (`Bearer`, `token=`, `secret=`, `password=`, `api_key=`);
   - в `random.crypto_int` устранён modulo bias с помощью rejection sampling;
   - `cargo test` после правок 0.13.0: 30/30 passed.

### Что остаётся открытым (после 0.13.0)
- Файловая песочница по-прежнему является in-process политикой (TOCTOU, hard links).
- Интерактивное GUI, Job Object и реальный clipboard требуют ручной проверки на Windows.
- Замена числовых handles в `mem` на непрозрачные дескрипторы с `Drop` остаётся в плане.

## Изменения и аудит 0.14.0 – 0.14.2

1. **Исправление смещения локальных слотов и верификатора байткода (`compiler.rs`, `bytecode.rs`):**
   - в `compiler.rs` добавлен учёт `temp_depth` (`stack_height()`), чтобы `Expr::ListComp`, `Expr::Block`, `Expr::Match` и `Expr::TryCatch` внутри составных выражений не затирали временные операнды на стеке VM;
   - `Compiler::local_count` теперь учитывает локальные переменные, захваченные только через `UpvalueDesc` (`is_local: true`);
   - внутренние переменные циклов и `match` переименованы с префиксом `$` (`$for_iter`, `$match_subject`, `$comp_iter` и др.), недоступным из пользовательского синтаксиса;
   - в `verify_proto` добавлена проверка соответствия длины `upvalue_lists` и границ индексов `UpvalueDesc`.
2. **Устранение zombie-фреймов в `VM::call_value` и перехвата лимитов песочницы (`vm.rs`, `test.rs`):**
   - `VM::call_value` теперь корректно раскручивает `frames`, `stack`, `open_upvalues` и `try_handlers` при ошибке внутри вызываемого замыкания (ранее при вызове через `test.assert_err` код после ошибки мог продолжить выполнение);
   - фатальные ошибки песочницы (`Sandbox instruction limit exceeded` и `Execution timeout`) больше не могут быть перехвачены или подавлены через `try / catch` или `test.assert_err`, в том числе внутри `map`/`filter`/`reduce` и `process.run()`.
3. **Защита файловой песочницы от UNC/SMB-утечек, оракула существования файлов и дропа бинарников (`vm.rs`, `fs.rs`):**
   - заблокированы UNC-пути (`\\server\share`, `//server/share`), пространства имён устройств (`\\.\`, `\\?\`), `CLOCK$` и drive-relative пути (`C:file`), что предотвращает исходящие SMB-обращения и утечку NTLMv2-хешей в режиме песочницы;
   - добавлена лексическая проверка принадлежности пути к `sandbox_root` / `allow_read` / `allow_write` до обращения к файловой системе, устраняющая оракул проверки существования внешних файлов и папок по тексту ошибки ОС;
   - в `fs.write` и `fs.append` добавлены проверка симлинков, лимит 32 MiB и запрет записи исполняемых/скриптовых расширений (`.exe`, `.dll`, `.bat`, `.cmd`, `.ps1`, `.vbs`, `.msi` и др.) в режиме песочницы;
   - исправлена каноникализация многоуровневых новых путей для `fs.mkdir("a/b/c")`.
4. **Изоляция `process.run()`, учёт `--timeout` в `sleep`/`http`/`dialog` и защита от DoS (`process.rs`, `sys.rs`, `time.rs`, `glob.rs`, `strings.rs`, `regex.rs`, `gfx.rs`, `dialog.rs`, `main.rs`):**
   - `process.run()` на Windows изолирует дочерние процессы через Job Object (`JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`), проверяет `--timeout` (даже с `--unsafe`) и запрещает обход `--allow-exec=cmd` через относительные пути с разделителями;
   - `sys.sleep` и `time.sleep_ms` ограничены остатком времени `--timeout`;
   - в `glob.match` устранён экспоненциальный backtracking $O(2^N)$ и снято искусственное ограничение глубины 64 символа на длину пути;
   - добавлены лимиты размера результата для конкатенации строк (64 MiB), списков (`10_000_000` элементов), `strings.replace`, `strings.join`, `regex.replace`, а также лимиты объектов `gfx` (`IMAGES`, `texts`) и флаг `OFN_NOCHANGEDIR` в файловых диалогах;
   - `askane permissions` теперь рекурсивно обходит всё AST (включая вложенные блоки и функции), учитывает `process`, `dialog`, `audio` и транзитивно проверяет локальные импорты `.ask`;
   - `cargo test` после правок 0.14.2: 36/36 passed.

## Изменения и аудит 0.14.3

1. **Таймауты, CLI и пути песочницы (`vm.rs`, `main.rs`, `fs.rs`):**
   - в `VM::execute` введён независимый `step_counter`, чтобы `--timeout` срабатывал даже при `--unsafe` (`max_instructions == None`); в CLI явные `--timeout` и `--max-steps` больше не затираются порядком флага `--unsafe`;
   - относительные `--allow-read` / `--allow-write` резолвятся относительно стартового CWD CLI и поддерживают ещё не созданные каталоги через каноникализацию существующего предка; в `normalize_lexical` учтены Windows-префиксы `\\?\` и регистронезависимость;
   - `askane permissions` ограничивает глубину импортов (`depth < 32`), а не общее число файлов `visited`, и не подавляет ошибки импортируемых `.ask` файлов; `collect_ask_files` пропускает симлинки и отслеживает посещённые директории;
   - `fs.copy()` ограничен регулярными файлами и лимитом `MAX_FS_BYTES` (32 MiB); `fs.remove()` и `fs.move()` работают с самим симлинком внутри песочницы без удаления/перемещения его цели; `fs.glob()` корректно проверяет пути при вызове из подкаталога модуля.
2. **Процессы, GUI Studio и графика (`process.rs`, `gui.rs`, `gfx.rs`):**
   - `process.run()` ожидает потоки чтения `stdout`/`stderr` с периодической проверкой `vm.check_timeout()` и принудительно завершает `ProcessJob` / группу процессов `-pgid`, если потомок оставил фоновый процесс с открытыми пайпами;
   - в `gui.rs` устранена гонка закрытия `child_job` / `child_stdin` в фоновом потоке, добавлен `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` для Job Object и очистка временного файла на всех путях ошибки;
   - `gfx` очищает кэш `IMAGES` и `LAST_FRAME` в `gfx.close()` и при `Drop` у `VM`.
3. **VM, компилятор, парсер и стандартная библиотека (`compiler.rs`, `parser.rs`, `bytecode.rs`, `value.rs`, `glob.rs`, `regex.rs`, `math.rs`, `datetime.rs`):**
   - исправлена рекурсия локальных и модульных функций (`Stmt::FnDecl` при `scope_depth > 0`), добавлена проверка числового типа в `Pattern::Range` и однократное вычисление объекта/индекса при составном присваивании;
   - устранены паники переполнения в `Op::Slice`, `math.abs(i64::MIN)` и `datetime.parse_iso` (плюс проверка валидности дней месяца);
   - ограничена работа на DAG-графах в `Value::equals_depth` (мемоизация + бюджет) и `Value::fmt_with_seen`, а в `unique`/`sort`/`flatten`/`map`/`filter`/`reduce`/`any`/`all`/`find` добавлен `vm.check_timeout()`;
   - `glob.match` переписан на итеративный DP с корректной границей сегмента `**/`; в `regex` счётчик backtracking привязан к стартовой позиции, добавлена проверка таймаута, экранирование в `[...]` и ошибка при превышении лимита замен в `regex.replace`;
   - `verify_proto_depth` проверяет `Op::MakeModule` и запрещает `Constant::Function` в `Op::Constant`; `format_askane_source` и `needs_more_input` корректно обрабатывают `"""..."""`, `r"..."` и `/* ... */`.
   - `cargo test --locked` после правок 0.14.3: 37/37 passed.

## Реализованные меры безопасности и стабилизации (0.15.0)
1. **Единый бюджет ресурсов `ResourceBudget` (`vm.rs`, `modules/*`, `main.rs`, `gui.rs`):**
   - аллокации (`bytes`, строки, списки, словари, множества, структуры), I/O-байты и стоимость тяжёлых нативных операций (`strings.repeat`/`replace`/`join`, `base64`, `hex`, `hash`, `fs`, `random`) проверяются через `charge_alloc` / `charge_io` / `charge_work` с поддержкой `--max-mem=MB`;
   - ошибки исчерпания бюджета памяти/I/O помечены как unrecoverable в `is_unrecoverable_error`, чтобы `try`/`catch` и `test.assert_err` не могли их подавить.
2. **Изоляция `askane.toml` и многофайловых модулей (`main.rs`, `vm.rs`, `compiler.rs`):**
   - `askane.toml` является строго декларативным (`entry`, `tests`, `[limits]`): любые поля/секции вроде `[permissions]`, `allow_*`, `sandbox = false` или `unsafe` игнорируются и никогда не выдают привилегий песочницы; пути `entry` и `tests` проверяются на отсутствие абсолютных путей и выхода `..` за корень проекта (`resolve_manifest_subpath`);
   - относительные импорты внутри модулей разрешаются относительно `Closure.base_dir` самого импортирующего модуля и строго проверяются на границы `sandbox_root` (`resolve_read_path_from`); `askane permissions` отслеживает транзитивные импорты `from ... import` и пакеты директорий `mod.ask`.
3. **Безопасность новых конструкций и оптимизаций VM (`value.rs`, `bytecode.rs`, `parser.rs`, `vm.rs`, `main.rs`):**
   - `SetKey::from_value` отклоняет `NaN` и не-хешируемые мутабельные типы, сохраняет консистентность `Int`/`Float` и нормализует `-0.0`;
   - inline-кэши глобальных переменных и полей структур привязаны к монотонному `ic_epoch` (`self.frames.is_empty()`), что исключает коллизии при переиспользовании адресов `Rc<FunctionProto>`;
   - `Op::ForPrep`/`Op::ForIter` делают снимок при итерации по `set` и проверяют актуальную длину списка на каждой итерации; `verify_proto_depth` валидирует `Constant::Struct`, `kw_lists`, `JumpIfArgPresent`, `ForPrep`/`ForIter`; `askane fmt` проверяет синтаксис через `Lexer` и `Parser` до и после форматирования.
   - `cargo test --locked` после правок 0.15.0: 41/41 passed.
